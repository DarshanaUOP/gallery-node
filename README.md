# Luminary — Local Media Gallery

A lightweight, local-first photo and video gallery. Index media from your filesystem, browse with a refined dark UI, organise into albums, and manage visibility — no cloud dependency, no accounts, no tracking.

---

## Requirements

- Python 3.8+
- ffmpeg (for video thumbnails and metadata — `apt install ffmpeg` or `brew install ffmpeg`)

---

## Installation

```bash
# 1. Clone / download the project folder
cd luminary

# 2. Install Python dependencies
pip install flask flask-cors Pillow pillow-heif
```

`pillow-heif` is optional but recommended for native HEIC/HEIF support. Without it, Luminary falls back to system ImageMagick or ffmpeg for HEIC decoding.

---

## Quick Start

```bash
chmod +x run.sh
./run.sh
```

Then open **http://localhost:5000** in your browser.

To run an initial sync before starting the server:

```bash
./run.sh --sync
```

Or start the backend directly:

```bash
python3 app.py                  # start server on port 5000
python3 app.py --port 8080      # custom port
python3 app.py --sync-only      # scan directories and exit, no server
```

## Configuration

### `data/media.json` — Source directories

Add the directories you want Luminary to scan. Luminary recurses into all subdirectories automatically.

```json
[
  {
    "name": "Travel Photos",
    "path": "/Users/you/Pictures/Travel",
    "visibility": true
  },
  {
    "name": "Family",
    "path": "/Users/you/Pictures/Family",
    "visibility": true
  },
  {
    "name": "Old Archive",
    "path": "/Volumes/Backup/Photos",
    "visibility": false
  }
]
```

| Field | Description |
|---|---|
| `name` | Human-readable label shown in the Locations filter |
| `path` | Absolute path to the root directory |
| `visibility` | `false` skips this source during Sync without deleting it |

You can also manage this file through the UI via **⊞ Locations** in the top bar.

### `data/configuration.json` — App settings

```json
{
  "thumbnail_size": 400,
  "thumbnail_quality": 60,
  "thumbnail_cache_path": "/path/to/your/thumb_cache",
  "lazy_load_batch": 50,
  "supported_image_formats": ["jpg","jpeg","png","heic","heif","webp","tiff","bmp","gif"],
  "supported_video_formats": ["mp4","mov","avi","mkv","webm","m4v","3gp","wmv","flv","ts","mts"],
  "show_hidden_default": false,
  "api_port": 5000,
  "log_level": "INFO"
}
```

| Key | Default | Description |
|---|---|---|
| `thumbnail_size` | 400 | Max dimension of cached thumbnails in pixels |
| `thumbnail_quality` | 60 | JPEG quality for thumbnails (1–95) |
| `thumbnail_cache_path` | *(next to app.py)* | Absolute path to store thumbnail cache. Leave empty to use `.thumb_cache/` |
| `lazy_load_batch` | 50 | Number of images to render per scroll batch |
| `supported_image_formats` | see above | Image file extensions to index |
| `supported_video_formats` | see above | Video file extensions to index |
| `show_hidden_default` | false | Show hidden media on initial load |
| `api_port` | 5000 | Port the backend listens on |

## Syncing Media

Click **↻ Sync** in the top bar. The backend will:

1. Read all visible sources from `data/media.json`
2. Walk each directory recursively (including all subdirectories)
3. Skip already-indexed files (deduplication by resolved path and MD5 hash)
4. Extract EXIF/video metadata for each new file
5. Save results to `data/db.json`

New media appears in the gallery immediately after sync — no page refresh needed.

Trigger sync from the command line:

```bash
curl -X POST http://localhost:5000/api/sync
```

## Features

### Gallery
- **Responsive grid** — 4 columns on desktop, scales to 2 on mobile
- **Lazy loading** — media loads in configurable batches as you scroll
- **Scroll date indicator** — floating pill shows the date range of currently visible items while scrolling
- **Subdirectory path badge** — faint label on each card shows which subfolder it came from

### Filtering & Sorting
- **Sort** by newest/oldest (modified date with created date fallback) or filename
- **Filter** by format, camera model, and source location
- **Search** by filename, camera make/model, or date

### Media Viewing
- **Lightbox** for images — progressive load (blurred thumbnail → full resolution), keyboard navigation (← → Esc)
- **Video player** — native browser `<video>` element with HTTP range-request streaming; supports seeking without downloading the full file
- **HEIC/HEIF** — transcoded to JPEG on the fly for browser compatibility
- **Unsupported formats** — shows a clear error with a download link instead of a black screen

### Albums
- Create, rename, and delete albums
- Add photos via the **photo picker** (thumbnail grid with search and location filter)
- Add individual photos via the per-card context menu (⋮)
- Remove photos from an album via the context menu when inside that album

### Media Management
- **Hide / unhide** individual items via context menu
- **Locations manager** (⊞ Locations) — add, edit, delete, and toggle visibility of source directories without editing JSON manually
- **Full metadata viewer** — EXIF data, GPS coordinates, video codec, resolution, duration

### Thumbnail Cache
Thumbnails are generated once and cached to disk. The cache directory is configurable via `thumbnail_cache_path` in `configuration.json`. Cached thumbnails are reused on all subsequent requests, including for HEIC and video files.

## API Reference

| Method | Path | Description |
|---|---|---|
| GET | `/api/db` | Combined `{media, albums}` — used by the frontend |
| POST | `/api/db` | Save `{media, albums}` — splits into `db.json` and `albums.json` |
| GET | `/api/media` | Media array only |
| GET | `/api/albums` | Albums array only |
| GET | `/api/config` | App configuration |
| GET | `/api/thumb/<id>` | Thumbnail JPEG (cached, 400px default) |
| GET | `/api/image/<id>` | Full-resolution image |
| GET | `/api/video/<id>` | Video stream with range-request support |
| POST | `/api/sync` | Scan directories and index new media |
| GET | `/api/locations` | Read `data/media.json` |
| POST | `/api/locations` | Update `data/media.json` |
| POST | `/api/album/create` | `{"name": "Album Name"}` |
| POST | `/api/album/add` | `{"albumId": "…", "uniqueName": "…"}` |
| POST | `/api/media/hide` | `{"uniqueName": "…", "hidden": true}` |

## Data Files

| File | Tracked in git | Description |
|---|---|---|
| `data/configuration.json` | ✗ | App settings — auto-created with defaults on first run |
| `data/media.json` | ✗ | Source directory list — auto-created with defaults on first run |
| `data/db.json` | ✗ | Indexed media — generated by Sync |
| `data/albums.json` | ✗ | Albums — generated by the app |
| `logs/log-YYYY-MM-DD.log` | ✗ | Daily rotating log |

All files in `data/` are git-ignored. On first run, `app.py` creates `configuration.json` and `media.json` with sensible defaults if they do not exist. Edit them to point at your photo directories and tune settings before running Sync.

---

## Logs

Luminary writes a daily log file to `logs/log-YYYY-MM-DD.log`. Logs rotate at midnight and are retained for 30 days. All log files are git-ignored. Output is also printed to the terminal.

## Troubleshooting

**No photos after Sync**
- Check that paths in `data/media.json` are absolute and the directories exist
- Confirm `visibility: true` on the desired sources
- Check terminal output or today's log file for scan errors

**HEIC images not loading**
- Install `pillow-heif`: `pip install pillow-heif`
- Or install system ImageMagick: `brew install imagemagick` / `apt install imagemagick`

**Videos not playing**
- Install ffmpeg: `brew install ffmpeg` / `apt install ffmpeg`
- MOV files recorded on iPhone with HEVC codec will not play in Chrome — Safari supports them natively, or transcode to H.264 MP4

**Thumbnails not generating for videos**
- ffmpeg must be on your PATH: `which ffmpeg`

**Backend not reachable**
- Check `app.py` is running: `ps aux | grep app.py`
- Check for port conflicts: `lsof -i :5000`
- Try a different port: `python3 app.py --port 8080`
